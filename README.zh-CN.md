# dsh-fine-tune · 模型微调工作台

**给 DSH 的微调流水线：从真实会话里抽「情景 → 应做动作」样本，审数据、去重、脱敏，本地或远端 GPU 跑 QLoRA，先 A/B 对比再发布。**

[English](README.md) · MIT · [设计方案](DESIGN.md) · [M0 实验手册](M0-LAB.md)

## 为什么

市面上不缺训练脚本，缺的是「训什么、数据干不干净、训完到底有没有变好」这一整条链：

1. **训什么**：DSH 的会话历史本身就是成规模的 `(情景 → 应做动作)` 数据，但里面混着失败重试、幻觉工具名和私密信息；
2. **干不干净**：数据集会被上传、会被学进权重，脱敏与去重是必须的，而且要在训练**之前**给出证据（数据卡）；
3. **有没有变好**：「回答好不好」不可判定，但「工具名对不对、参数对不对、有没有编造工具」可以——有回退就不许发布。

## 你会看到什么

一个侧栏入口「模型微调」、五个模型工具，按「数据 → 训练 → 评测」三段布置。

| 入口 | 用途 |
|---|---|
| `train_prepare` | **最常用**：选会话或本地文件 → 建数据集 + 数据卡（保留/去重/丢弃原因/脱敏次数/token 分布） |
| `train_check` | 这台机器能不能练？显卡、**两种训练方式各自的**显存预估逐项、最小的一个改动建议 |
| `train_run` | 启动训练（放不下会在启动前就拒绝，而不是十分钟后 OOM） |
| `train_status` | 任务状态、loss、产物、评测结论 |
| `train_eval` | 这次训练怎么评、上次结论是什么 |
| **面板** | 见下 |

## 两种训练方式（面板里一键切换）

| | **QLoRA** | **LoRA** |
|---|---|---|
| 底座 | 4bit 量化（NF4 / FP4，可选双量化） | fp16 全精度 |
| 质量 | 接近 LoRA，量化有轻微噪声 | 最稳，无量化噪声 |
| 显存 | 省：0.5B @ seq1024 实测 **2.9 GiB** | 高：同一模型约 2.5 倍 |
| 6 GB 能跑 | **0.5B @ seq1024**、1.5B @ seq256 | 更小的模型 |
| 6 GB 建议 | **默认** | 只有在小模型上追求最高质量时才选 |

> 这些数字来自 M0 实测（RTX 3060 Laptop 6 GB）。早期版本的预估把显存低估了约 20 倍——
> 漏了 logits 项（vocab × seq × 4 字节）与逐层激活保留。现在预估偏保守 10–17%，
> 详细测量见 [M0-LAB.md](M0-LAB.md) §7。

两者都走 LoRA 适配器（r 4–64），切换方式只影响**底座怎么装进显存**；显存预估会按方式分别算，放不下时给出的建议也不同（先降序列 → 换 QLoRA → 换小模型）。

## 交互面板（四处都可操作）

**① 训练参数**：方式切换、底座模型、序列长度、轮数、学习率、LoRA r、batch、量化类型 / dropout——全部可改，前端先按与后端同一套规则校验，改完实时重算显存。

**② 样本预览与剔除**：按 train/val/eval 分页看每一条样本的「提示（情景）」和「标签（应做的动作）」，看到坏样本点「移除」即可；移除是**可恢复**的，并且会真正进到下一次训练的数据里（训练启动时物化过滤后的数据集，而不是只改界面）。

**③ 对比评测（四步对话式）**：
1. 取 6 道评测题；
2. 按题填「底座」「微调后」两列回答；
3. 复制裁判提示词（带当时可用的工具列表，A/B 顺序按样本哈希随机），贴给任意模型，把它返回的 JSON 判定贴回来；
4. 面板解析出「微调后赢 / 底座赢 / 平」，一键把结论记到任务上——记录的分数明确标注来源，不会伪造贴合度。

**④ 结论与发布**：贴合度对比、失败样例、发布门（绿灯 + `.gguf` 才解锁）。

## 安装

先把目录装进 profile（本机开发用 `file:`，发布用 npm 包名）：

```sh
dsh plugin --profile desktop add file:C:/Users/86156/Documents/deepseek-harness/default-workspace/fine-tune
```

重启 profile，侧栏出现「模型微调」。**默认全部只读**：看数据、看显卡都行，训练与发布要在插件配置里分别打开开关。

## 三个开关

| 开关 | 默认 | 打开后 |
|---|---|---|
| 允许启动训练进程 `allowSpawn` | 关 | 能开始训练、能探活 Python |
| 允许发布模型 `allowPublish` | 关 | 评测绿灯 + 有 `.gguf` 时才解锁发布准备 |
| 允许远端访问面板 `allowRemotePanel` | 关 | 面板路由不再只认本机回环 |

## 快速走一遍

1. **准备数据**：面板「数据」页选几个会话（不选 = 全部）→ 「建数据集」。看数据卡：保留多少、丢了什么、脱敏命中多少。
2. **看能不能练**：用工具 `train_check`，或面板「训练」页的显存预估。
3. **训练**：先在 `M0-LAB.md` 里装好 venv 并跑通一次 dry-run，再在面板里开始训练；曲线实时出。
4. **评测**：`python -m fnt_worker eval`（见 M0 手册）产出 `evaluation` 事件，结论回到面板。
5. **发布**：只有绿色结论才能「发布准备」，面板给出 `ollama create` 命令。

## 配置

```yaml
- id: fine-tune
  config:
    pythonPath: C:\\path\\to\\venv\\Scripts\\python.exe   # 装了 torch 的解释器
    workerRoot: C:\\path\\to\\fine-tune\\python           # 缺省 = 插件自带 python/
    dataDir: ""                                          # 缺省 ~/.dsh/fine-tune
    allowSpawn: false
    allowPublish: false
    nvidiaSmi: nvidia-smi
    sshTarget: ""                                        # M4：远端训练
```

## 诚实说明

- **M0 没跑完之前，「能训效果」是待验证的**。本机 6 GB 显存，1.5B 稳、4B 可试、7B 会拒绝。见 [M0-LAB.md](M0-LAB.md)。
- **评测的贴合度是机械检查**（工具名/参数/格式），不是主观质量分。
- **远端 SSH 训练接口已留但未接通**（宿主的 ssh 执行服务），当前只能用本地后端；清单在 [DESIGN.md](DESIGN.md) §10。
- 会话日志解码依赖对首帧保留位的那一处处理；读不出来的会话会**明说是读不出来**，不会被算成「空会话」。
- 数据卡里 `hallucinated_tool` 偏高通常是「工具注册表被重写过、旧工具仍在被调用」，不是模型幻觉——去重与剔除逻辑本身是对的。
